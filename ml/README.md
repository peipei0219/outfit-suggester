# outfit-ml

Outfit Suggester の機械学習部分です。

1. **服の写真から「種類・色・着る季節」を自動判定**（CLIP のゼロショット分類）
2. **手持ちの服どうしのコーデ相性を判定**（Polyvore Outfits で学習した相性モデル）

どちらもスマホのブラウザ内で動き、写真や服のデータは端末の外に出ません。

## しくみ

```
          ┌──────────── Python（このディレクトリ）────────────┐
タクソノミー  │ 服の種類 28 / 色 16                                  │
(taxonomy.py)│   └ 英語の呼び方 × プロンプトテンプレート             │
            │        └ CLIP テキストエンコーダ → 正規化 → 平均      │ ← プロンプトアンサンブル
            │             └ model/tagger.json（float16, 約60KB）   │
            └──────────────────────────┬───────────────────────────┘
                                       │ GitHub Pages で配信
            ┌──────────── ブラウザ（スマホ）─────────▼─────────────┐
写真 ──────▶│ CLIP 画像エンコーダ（transformers.js / ONNX, 端末内）  │
            │   └ 画像埋め込み · クラス重み → softmax → 上位候補     │
            └──────────────────────────────────────────────────────┘
```

- **写真は端末の外に出ません。** 画像側の CLIP はブラウザ内（WebAssembly）で動きます。
- **サーバー不要。** テキスト側はあらかじめ Python で計算し、静的ファイルとして配信します。
- **具体的な服の種類を当ててから、種類・季節に変換。** CLIP は「アウター」のような抽象的な区分より「ダウンジャケット」の方が当てやすいため。
- Python もブラウザも **同じ ONNX ファイル**（`Xenova/clip-vit-base-patch32`）を使います。画像側はブラウザと同じ 8bit 量子化版で評価するので、レポートの数値がそのままアプリでの精度になります。PyTorch は不要です。

## セットアップ

```bash
cd ml
uv sync --group dev                 # テストだけなら（モデル不要）
uv sync --group dev --extra clip --extra eval   # 書き出し・評価もするなら
```

## コマンド

```bash
uv run pytest                        # テスト（モデルのダウンロード不要）
uv run outfit-ml evaluate             # dev で設定を決め、test で精度を測る → reports/
uv run outfit-ml export              # model/tagger.json を作る（evaluate で決めた基準を使う）
```

## 評価

データ: `ashraq/fashion-product-images-small`（ファッション EC の商品画像 約 4.4 万枚、60×80px）。
商品 ID の偶奇で **dev（プロンプト・キャリブレーション・自動入力の基準を決める）** と **test（最終報告）** に分け、test の数値は調整に使っていません。
データセットのラベルはこのアプリの分類と 1 対 1 ではないので、「正解とみなす候補の集合」に変換して評価しています（`evaluate.py` の `ARTICLE_TYPE_MAP`）。

### 結果（test 側、1,260 枚）— 詳細は [reports/zeroshot_eval.md](reports/zeroshot_eval.md)

| | 服の種類 Top-1 | Top-3 | 種類（アウター/トップス/ボトムス） | 色 Top-1 | 色 Top-3 |
|---|---:|---:|---:|---:|---:|
| 単一テンプレート | 65.1% | 86.7% | 91.6% | 44.0% | 70.2% |
| プロンプトアンサンブル | 65.6% | 87.2% | 91.4% | 45.5% | 74.2% |
| **＋キャリブレーション（採用）** | **67.9%** | 86.7% | **91.8%** | **52.6%** | **79.4%** |

- **キャリブレーション**: CLIP は特定のクラスに予測が偏る（例: 黒い服の多くを「グレー」と予測）。dev 側の平均画像埋め込みに対する logit を各クラスの偏りとみなし、その 0.5 倍を差し引く（contextual calibration）。強さは dev で 0 / 0.5 / 1.0 を比べて決定。黒→グレーの誤りが 109 件 → 40 件に減った。
- **自動入力の基準**: dev 側で「正解率 85% 以上で自動入力される割合が最大」の基準を選び、`1位の確率 ≥ 0.7` を採用。test 側では **24.8% の写真で自動入力され、その正解率は 88.5%**。それ以外は上位 3 候補をタップで選ぶ。

### ブラウザとの一致（training/serving skew の確認）

同じ ONNX ファイルでも、画像の前処理（リサイズ）の実装が Python と transformers.js で異なる。test 側 48 枚（アプリと同じ長辺 480px）で比べた結果:

- 画像埋め込みのコサイン類似度: 平均 0.985、最小 0.970
- Top-1 の一致: 42 / 48。不一致 6 件はすべて確率 55% 以下の拮抗ケースで、**アプリで自動入力されるものはなし**

```bash
uv run python scripts/parity_export.py /tmp/parity
cd /tmp/parity && npm install --no-save @huggingface/transformers@3.0.2 && node <repo>/ml/scripts/parity.mjs
```

### わかっている限界と次の一手

- **評価データとアプリの写真は違う**: 評価は白背景の小さな商品画像。スマホで撮った服（ハンガー・床置き・着用）では精度が変わりうる。→ アプリでユーザーが直した結果を正解ラベルとして集める仕組みが必要。
- **色がまだ弱い（52.6%）**: 特にネイビー・ブラウン・白。→ 服の領域の画素から代表色を出す方法や、埋め込み上の線形分類器（linear probe）と比較する。
- **ニット・スウェット・レギンスが苦手**（Top-1 40% 前後）。データセットのラベル粒度の差もある。

## コーデ相性モデル

### しくみ

```
服の写真 ─▶ CLIP 画像埋め込み（自動入力のときに計算・服ごとに保存）
                 │
   アウター×トップス×ボトムスの組み合わせごとに
   2 着ずつの組の特徴 [a⊙b, |a−b|] + 種類の組 ─▶ 小さなニューラルネット ─▶ 相性スコア
                 │                                    （model/compat.json, 344KB）
   スコア上位 5 通りから重み付きで 1 つ選ぶ（「別の候補」で変化をつける）
```

- 学習データ: [Polyvore Outfits](https://huggingface.co/datasets/mvasil/polyvore-outfits)（Vasileva et al., ECCV 2018, CC BY 4.0）の **disjoint** 分割（train / valid / test でアイテムが重ならない＝初めて見る服への汎化を測れる）。
  公式はログインが必要なため、同じファイルを再配布している `Stylique/Polyvore` を使用。disjoint 分割の全ファイル（コーデ・FITB・相性判定）は公式と **SHA-256 が一致** することを確認した（画像は公式が parquet 形式のため未照合）。
- 対象はアプリの種類（アウター・トップス・ボトムス）のアイテムだけ。正例 = 同じコーデに入っている別の種類の 2 着、負例 = 片方を同じ種類のランダムなアイテムに替えたもの（正例の 2 倍）。
- train で学習 → valid でモデルとハイパーパラメータを選択 → test で最終評価。

### 結果（test）— 詳細は [reports/compat_eval.md](reports/compat_eval.md)

| モデル | FITB（4 択の空欄補充） | 相性判定 AUC |
|---|---:|---:|
| ランダム | 25.8% | 0.501 |
| CLIP の類似度（学習なし） | 36.9% | 0.594 |
| ロジスティック回帰（種類の組ごと） | 38.3% | 0.620 |
| **ニューラルネット（採用）** | **40.8%**（±1.6%） | **0.657** |

- 学習なしの CLIP 類似度でもランダムより大幅に良い（色・雰囲気が似た服は合わせやすい）。学習でさらに +3.9pt。
- 論文の値（FITB 約 55.7%、AUC 0.84）は全カテゴリ（靴・バッグなど）を手がかりに使い、画像モデルも学習しているため問題設定が異なり、直接は比べられない。この差は次の改善点（下記）。
- Python と JavaScript で同じ相性スコアになることをテストで保証（`tests/fixtures/compat_parity.json`）。
- アプリでの確認: 3 つのコーデ（9 着）をクローゼットに入れて 30 回「別の候補」を押すと、トップスとボトムスは 30 回とも同じ元コーデの組になった（ランダムなら約 1/3）。

### コマンド

```bash
uv sync --group dev --extra clip --extra train
uv run outfit-ml compat-embed     # Polyvore の約 4.6 万アイテムを CLIP で埋め込み（CPU 4 コアで約 25 分、ml/data/ にキャッシュ）
uv run outfit-ml compat-train     # 学習・評価・model/compat.json の書き出し（約 5 分）
```

### 次の改善

- **種類ごとの埋め込み空間**（type-aware embedding, Vasileva et al.）や、コーデ全体を一度に見る **Transformer / set モデル**
- **難しい負例**（同じ種類で見た目が近いアイテム）での学習
- 靴・バッグも含めた評価（アプリ側に種類を増やす必要がある）
- アプリで「この組み合わせを着た / 却下した」を記録し、ユーザーごとに相性を調整する（ステップ 3）

## ファイル

| ファイル | 役割 |
|---|---|
| `taxonomy.py` | 服の種類・色の定義。アプリのキーと一致することをテストで確認 |
| `prompts.py` | プロンプトテンプレート |
| `classifier.py` | 埋め込み → 確率の計算（numpy のみ、ブラウザ側と同じ計算） |
| `clip.py` | ONNX Runtime で CLIP を動かす（ブラウザと同じ ONNX ファイル） |
| `export.py` | `model/tagger.json` の書き出し |
| `evaluate.py` | 評価用のラベル変換と指標 |
| `cli.py` | `outfit-ml` コマンド |
| `compat/polyvore.py` | Polyvore Outfits の読み込み（disjoint 分割、FITB・相性判定の問題） |
| `compat/models.py` | 相性モデル（ランダム・CLIP 類似度・ロジスティック回帰・MLP） |
| `compat/train.py` | 学習データの作成、FITB・AUC の評価 |
| `compat/embed.py` | アイテム画像の CLIP 埋め込みとキャッシュ |
| `compat/run.py` | 学習・選択・評価・書き出しの手順 |
